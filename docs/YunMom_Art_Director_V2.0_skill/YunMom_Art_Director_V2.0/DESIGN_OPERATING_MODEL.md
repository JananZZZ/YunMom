# YunMom visual operating model

## Core loop

Contract load → evidence/privacy classification → discover → generate or implement → hard-gate → independent review → integrate → capture synthetic evidence → critique → refine → user finalists → record feedback → aesthetic Golden → propagate → platform matrix → professional sign-off.

The user participates at finalist choice and aesthetic approval, not at production micro-decisions.

## Gate sequence

- **G0 Baseline ingestion:** contracts, visual state, reference roles, target implementation; no unbounded art generation.
- **G1 YunMom Master:** original identity plus Style Lock evidence.
- **G2 Baby anchor family:** stage-scoped anchors; production verification requires approved medical sources and qualified review; support `1..N BabySubject`.
- **G3 HOME Canonical:** Normal, Silent Day, ambient states, R0–R3 entry/detail, voice/camera and sensitive-state behavior.
- **G4 Visual system:** governed semantic Token version and generated Flutter/Rive/iOS Widget/Android Widget mappings.
- **G5 Core spaces:** CARE, MEMORY, KNOW, AI Overlay, reports and clinical-detail patterns.
- **G6 Motion/runtime:** layer contracts, state charts, Reduce Motion, pause/background/fallback and performance ownership.
- **G7 Real integration:** real Flutter/native UI; no flattened-screen shortcut.
- **G8 Platform/state matrix:** Android-first development evidence plus required iOS/Widget, accessibility, privacy, deletion, performance and failure matrices before public release.
- **G9 Visual release candidate:** immutable evidence manifest bound to source Tag/Build Hash and professional Go/No-Go. This is not reached by creative approval alone.

## Convergence and invalidation

After a valid Golden exists, vary only request-relevant dimensions. Never overwrite it. New contracts, professional findings, source-hash changes, invalid evidence, or a replacement parent may mark it and all dependents stale. A stale Golden can remain historical without being eligible for new production work.
